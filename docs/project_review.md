модель и порядок строк в версии артефактов, затем согласовать параллелизм
inference. Технические тесты с временными данными не измеряют качество цены.

## Архитектура и текущее поведение

Проект использует src-layout, общие dataclass-контракты в `schemas.py` и
отдельные модели HTTP-ответа. CLI и FastAPI вызывают один `pipeline.estimate`:
preprocess → encode → classify/retrieve → predict_price. Это позволяет
проверять HTTP отдельно от тяжёлой модели, сохраняя общий путь обработки.

Денис реализовал RGB-предобработку 224×224, CLIP ViT-B-32 и zero-shot
классификацию по текстовым промптам. Модель и текстовые векторы кэшируются.
`style` пока всегда None; confidence — softmax по промптам, его нельзя
считать проверенной вероятностью правильного ответа.

FAISS IndexFlatIP выполняет точный поиск по нормализованным векторам.
Индекс строится один раз; пустой каталог возвращает пустой список. Это
подходит для небольшого каталога, но поиск линейный по его размеру.
Каталог хранится в памяти процесса: каждый worker загрузит свою копию.

Цена — средневзвешенная по неотрицательной части сходства среди аналогов
с известной ценой. При нулевой сумме весов используется простое среднее.
Без цен аналогов берётся медиана категории; без неё возвращается None.
Диапазон цен внутри PricePrediction — минимум/максимум аналогов, не
доверительный интервал. Валюта пока фиксирована RUB. Категория не фильтрует
аналогов, поэтому похожий визуально предмет другого типа может влиять на цену.

Парсер получает карточки, цены и фотографии. `build_embeddings.py` считает
векторы пакетами, сохраняет NPZ и CSV и продолжает работу по lot_id.
Новый загрузчик приложения потребляет именно этот формат. Каноническая
категория CSV используется для fallback, чтобы совпадать с классификатором.

## Четыре законченных изменения

Первая пара — корректность поиска и оценки:

1. Копирование векторов перед нормализацией FAISS, проверка формы и конечности
   значений, положительного top_k. Неудачная загрузка сохраняет старый индекс.
   Тесты включают read-only массивы и проверку неизменности входных данных.
2. Контракт price допускает None до HTTP-ответа включительно. Тесты отличают
   отсутствие оценки от известной нулевой цены и сохраняют fallback категории.

Вторая пара — граница HTTP и интеграция:

3. Чтение UploadFile ограничено лимитом плюс один байт. Декодирование
   преобразует изображение в RGB; обрабатываются ошибки формата, чтения и
   лимита декодера. Проверены превышение размера и точная граница лимита.
4. Загрузка NPZ/CSV при старте API и через --catalog-dir в CLI. Проверяются
   размерность, число строк, уникальность ID и допустимость цен. Пропуски
   метаданных преобразуются в None. Добавлены интеграционные тесты HTTP и
   отдельный slow-тест с настоящим encoder и classifier.

Это две смысловые пары, а не утверждение о выполнении в разные недели.
Коммиты создаются с фактическими датами; историю команды не переписываем.

## Замечания преподавателя

Нормализация больше не меняет массивы вызывающего кода. Отсутствие данных
не получает ценник 0. Лимит файла проверяется после ограниченного чтения.
Появился загрузчик артефактов настоящего каталога, а реализованные стадии
Дениса включены в путь приложения без изменения их кода.

Проверка чтения не ограничивает целиком HTTP-тело на уровне сервера:
multipart-парсер работает раньше обработчика. Для публичного развёртывания
нужны ограничения тела запроса и параллелизма на уровне сервера/прокси.

## Что ещё требует работы

- В рабочей копии нет настоящего датасета. Временный каталог проверяет
  техническое соединение, но не качество поиска и цены на реальных лотах.
  Следующий шаг — получить артефакты Дениса и вручную разобрать несколько
  независимых запросов, исключая сам запрашиваемый лот из каталога.
- Нет измерений ошибки цены, размеченной проверки классификации и порога
  сходства для отказа от слабых аналогов. Порог нельзя выбирать наугад.
- В CUDA-пути Дениса обнаружены потенциальные несоответствия устройств:
  get_model не переносит модель на device, encoder нормализует CPU-тензор
  константами на выбранном device. Текущая машина CPU, поэтому CUDA не
  проверена. Перед использованием GPU исправить совместно с Денисом.
- open_clip предупреждает о несовпадении QuickGELU конфигурации модели
  и весов openai. Технические тесты проходят, но конфигурацию активации
  нужно согласовать с Денисом до измерений качества и пересчёта каталога.
- Повторное построение каталога пропускает уже известные lot_id: изменения
  цены или метаданных такого лота не обновляются автоматически. У NPZ/CSV
  нет общей версии, идентификатора модели и атомарного сохранения пары.
  Одинаковая размерность не доказывает совместимость моделей или порядок строк.
- Загрузка fallback отдельно от загрузки индекса не является транзакцией.
  Сейчас инициализация предназначена для старта процесса; горячую замену
  каталога нельзя делать без отдельного решения для общего состояния.
- Синхронный inference вызывается из async HTTP-обработчика и блокирует
  event loop. Для нескольких запросов нужна управляемая очередь/пул и
  измерение памяти, особенно если модель работает на GPU.
- pyproject объединяет runtime, инструменты данных и pytest; httpx находится
  в dev-extra. В CI пока нет workflow. Следующая небольшая задача — запуск
  быстрых тестов в CI и воспроизводимая установка из uv.lock.
- CLI обрабатывает только отсутствие изображения; повреждённые файлы и
  ошибки каталога пока выводят traceback. Полезно добавить понятные сообщения.
- README дополнен инструкциями, но локальный dev_log содержал устаревшие
  сведения о заглушках. Его следует использовать только как историю решений.

## Что показать на практике

Запустить быстрые тесты и объяснить три исправления из ревью. Затем выполнить
slow-тест интеграции из README: он создаёт каталог из настоящих эмбедингов
тестовой картинки и отправляет фото через HTTP. Отдельно показать запуск
с каталогом Дениса, когда появятся его файлы. Ожидаемая цена в тесте задана
временными метаданными и не является результатом оценки реального предмета.

## Результаты проверки

На Python 3.14, CPU: 45 быстрых тестов и 8 slow-тестов прошли, включая
настоящий путь через CLIP, классификатор, FAISS, оценку цены и HTTP.
`compileall` и `git diff --check` также прошли.

Загрузка Hugging Face в этом окружении зависала/обрывалась. Для ML-проверки
исходные веса скачаны из хранилища OpenAI с проверкой SHA-256, их state_dict
сохранён в safetensors в локальном кэше. После этого штатные тесты выполнены
с `HF_HUB_OFFLINE=1`, без подмены encoder/classifier или параметров модели.
Веса и данные в репозиторий не добавляются.
